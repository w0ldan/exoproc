While Oracle deprecated and removed the Nashorn JavaScript engine starting with Java 15, Exoproc's **`njava-runtime`** recreates the entire Nashorn environment with modern TypeScript and ES2024 features—delivering high-performance scripting across Java 8 through 25+.

Scripts executed via `exoproc run <script.ts>` or embedded in TypeScript applications enjoy full access to target Java objects as though they were native JavaScript variables.

```text
TypeScript Automation Script (script.ts)
                    │
                    ▼
          njava-runtime Engine
  ┌─────────────────────────────────────┐
  │ Pre-bound Globals:                  │
  │ • Java (Nashorn compatibility shim) │
  │ • print / console                   │
  │ • mc (Target client instance)       │
  │ • currentScreen                     │
  └─────────────────────────────────────┘
                    │
                    ▼
          Active Target JVM
```

## Running Scripts: `exoproc run`

Run any script against the attached Minecraft or Java process:

```bash
# Execute local automation script
exoproc run my-bot.ts

# Run with custom parameters or target PID
exoproc run --pid 12345 scripts/mine.ts
```

## Nashorn Compatibility Shims

`JavaContext` provides identical globals to legacy Nashorn scripts, ensuring backwards compatibility with older Minecraft bot engines while upgrading them to modern V8/Bun speeds:

### 1. `Java.type(className)`

Resolves static classes and enables constructor instantiation:

```typescript
const ArrayList = Java.type('java.util.ArrayList');
const list = new ArrayList();
list.add('Diamond Sword');
list.add('Golden Apple');
console.log(list.size()); // 2
```

### 2. `Java.from(javaCollectionOrArray)`

Converts Java lists, sets, and native arrays into standard JavaScript arrays:

```typescript
const players = Java.from(mc.theWorld.playerEntities);
players.forEach((p) => {
  console.log(`Player: ${p.getName()} at (${p.posX}, ${p.posY}, ${p.posZ})`);
});
```

### 3. `Java.to(jsArray, javaType)`

Converts JavaScript arrays into typed Java arrays:

```typescript
const jsNumbers = [10, 20, 30, 40];
const javaIntArray = Java.to(jsNumbers, 'int[]');
```

### 4. `Java.extend(superType, implementations)`

Subclasses or implements Java interfaces directly using JavaScript objects:

```typescript
const Runnable = Java.type('java.lang.Runnable');

const MyTask = Java.extend(Runnable, {
  run: () => {
    print('Task executed from JavaScript callback!');
  },
});

const taskInstance = new MyTask();
taskInstance.run();
```

## Automatic Exception Unwrapping

In standard JNI or reflection code, Java exceptions are wrapped inside deep layers of `InvocationTargetException` and `UndeclaredThrowableException`, obscuring the actual root cause.

`njava-runtime` automatically inspects thrown Java throwables, extracts the root cause, and wraps it into a standard native JavaScript `Error`:

```typescript
try {
  const BadClass = Java.type('non.existent.Class');
} catch (err: any) {
  // Directly caught as a JavaScript error
  console.error(err.message); // "ClassNotFoundException: non.existent.Class"
}
```

## Programmatic Script Runner API

You can also use the script runner programmatically inside your own tools:

```typescript
import { ScriptRunner } from 'njava-runtime';

const runner = new ScriptRunner({
  context: javaContext,
  globals: {
    customConfig: { speed: 1.5 },
  },
});

const result = await runner.execute(`
  const mc = Java.type('net.minecraft.client.Minecraft').getMinecraft();
  print("Current player: " + mc.thePlayer.getName());
`);
```
