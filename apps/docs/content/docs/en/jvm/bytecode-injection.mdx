Once bytecode is generated using the dynamic compiler, Exoproc provides the **`ClassDefiner`** and **`ClassLoader`** architecture in `njava-runtime` to inject and register classes into the live target JVM's memory without restarting the application or saving files to disk.

```text
Compiled Bytecode (Uint8Array)
               │
               ▼
      Java.defineClass()
               │
   ┌───────────┴───────────┐
   ▼                       ▼
Auto / Unsafe         Agent / ClassLoader
Strategy              Strategy
   │                       │
sun.misc.Unsafe       java.lang.ClassLoader
defineClass()         defineClass()
   │                       │
   └───────────┬───────────┘
               ▼
     Active Target JVM
  Available to Java.type()
```

## The Four Injection Strategies

Exoproc models ClassLoaders as first-class JavaScript objects and provides four specialized definition strategies:

| Strategy          | Engine                        | Stealth         | Use Case                                                                      |
| ----------------- | ----------------------------- | --------------- | ----------------------------------------------------------------------------- |
| **`auto`**        | Automatic fallback resolver   | High            | Default mode; picks the best available mechanism.                             |
| **`unsafe`**      | `sun.misc.Unsafe.defineClass` | Maximum         | Completely stealthy; bypasses ClassLoader lookup locks.                       |
| **`classLoader`** | `ClassLoader.defineClass`     | Medium          | Standard JVM reflection; attaches to `LaunchClassLoader` or `AppClassLoader`. |
| **`agent`**       | In-process `njava-agent`      | High Throughput | High-speed batch injection when the agent is active.                          |

---

### 1. `UnsafeClassLoader` (Stealth Mode)

`UnsafeClassLoader` retrieves the hidden `theUnsafe` instance via `sun.misc.Unsafe` and invokes `defineClass` directly:

```typescript
import { ClassLoader } from 'njava-runtime';

// Create an Unsafe definer
const unsafeDefiner = ClassLoader.unsafe(javaContext);

// Injects the class without registering it into standard ClassLoader hierarchy
const InjectedClass = unsafeDefiner.define({
  className: 'org.exoproc.stealth.Payload',
  bytecode: myBytecodeBuffer,
});

// Immediately instantiate or invoke
const payload = InjectedClass.newInstance();
```

- **Why it matters:** Anti-cheat systems and integrity monitors often hook `ClassLoader.loadClass` or inspect classloader caches. `Unsafe.defineClass` sidesteps these hooks entirely.

---

### 2. Standard `ClassLoader` (LaunchClassLoader / AppClassLoader)

When classes need to be discoverable by other existing game classes (e.g. registered event handlers, Minecraft Forge mods, or Fabric mixins), they must be defined in the application's root `ClassLoader`:

```typescript
import { ClassLoader } from 'njava-runtime';

// Resolve the thread context classloader (e.g. net.minecraft.launchwrapper.LaunchClassLoader)
const contextLoader = ClassLoader.getContextClassLoader(javaContext);

// Define into the game's classloader
contextLoader.defineClass(
  'org.exoproc.injected.CustomGuiScreen',
  myBytecodeBuffer,
);

// Now standard game code can find it via Class.forName()
const ScreenClass = Java.type('org.exoproc.injected.CustomGuiScreen');
```

---

### 3. High-Speed `AgentClassLoader`

When connected via `njava-agent`, bytecode injection operates over high-speed RPC:

```typescript
import { ClassLoader } from 'njava-runtime';

const agentLoader = ClassLoader.agent(javaContext);
const HookClass = agentLoader.defineClass(
  'org.exoproc.agent.TickListener',
  myBytecodeBuffer,
);
```

## Convenience API: `Java.defineClass()`

Inside automation scripts running on `JavaContext`, `Java.defineClass` provides an ergonomic shorthand:

```typescript
// Compiles and defines in one fluid workflow
const result = await Java.compile(`
  package org.exoproc.test;

  public class Greeting {
      public static String message() {
          return "Hello from Injected JVM Memory!";
      }
  }
`);

// Define into target JVM
const GreetingClass = Java.defineClass(
  'org.exoproc.test.Greeting',
  result.classes.get('org.exoproc.test.Greeting')!,
);

console.log(GreetingClass.message()); // "Hello from Injected JVM Memory!"
```

## In-Memory JAR Packaging: `buildJarBuffer()`

If your injected classes depend on multiple assets, resources, or nested classes, you can package them into an in-memory JAR file on the fly:

```typescript
import { buildJarBuffer } from 'exoproc-jjit';

const jarBuffer = await buildJarBuffer([
  { path: 'META-INF/MANIFEST.MF', content: 'Manifest-Version: 1.0\n' },
  { path: 'org/exoproc/Task.class', content: taskBytecode },
  { path: 'org/exoproc/Task$1.class', content: taskInnerBytecode },
]);

// Inject or load the entire JAR into target ClassLoader
```
