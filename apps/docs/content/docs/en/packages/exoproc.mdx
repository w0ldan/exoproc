The `exoproc` package is the top-level orchestration layer of the framework. It consolidates the former daemon, tool runner, and client into a single unified, OS-aware package.

## OS-Aware Execution Model

Rather than requiring a background daemon on all operating systems, `exoproc` adapts its architecture based on the host operating system:

```text
┌────────────────────────────────────────────────────────────────────────┐
│                        exoproc (Unified CLI)                           │
└───────────────────────────────────┬────────────────────────────────────┘
                                    │
           ┌────────────────────────┴────────────────────────┐
           ▼                                                 ▼
     Windows (Native)                             Linux / Wine / macOS
┌─────────────────────────┐                       ┌─────────────────────────┐
│ Direct In-Process Tool  │                       │      Daemon Bridge      │
│ • No daemon required    │                       │ • Spawns exoproc daemon │
│ • Direct Win32 Memory   │                       │ • Communicates via      │
│ • Direct JNI & Hooks    │                       │   Loopback HTTP/SSE     │
│ • Zero IPC latency      │                       │ • Connects into Wine    │
└─────────────────────────┘                       └─────────────────────────┘
```

### 1. On Windows (Native Target)

On native Windows x64 systems, `exoproc` does not run an extraneous daemon. Instead, it runs **directly in-process** as a native tool:

- Binds directly to `bun-winapi`, `bun-xffi`, and `bun-njava`.
- Calls Win32 process and memory APIs directly.
- Executes automation scripts in the local Bun process with zero IPC overhead.

### 2. On Linux / Wine / macOS (Cross-Environment)

When developing or running automation from a Linux or macOS host targeting a Windows process inside Wine:

- `exoproc` automatically starts or connects to the Wine daemon bridge (`exoproc daemon`).
- Commands dispatch through local HTTP/SSE streaming endpoints (`127.0.0.1:43370`).
- Provides seamless remote inspection, screenshots, and command execution across host and Wine boundaries.

## CLI Commands

The `exoproc` binary provides a rich set of terminal commands:

### `exoproc run <script.ts>`

Executes automation scripts against the active target JVM with pre-bound globals (`Java`, `print`, `mc`, `currentScreen`):

```bash
exoproc run ./my-automation.ts
```

### `exoproc attach <target>`

Attaches to a running Minecraft or Java process by PID or window/executable name:

```bash
exoproc attach javaw.exe
exoproc attach 14208
```

### `exoproc screenshot`

Captures an in-memory OpenGL framebuffer screenshot from the game window and renders it directly in modern terminals using Kitty graphics or ANSI sixels:

```bash
exoproc screenshot --save ./capture.png
```

### `exoproc status`

Displays live attachment status, memory usage, attached target PID, and active bridge mode:

```bash
exoproc status
```

### `exoproc mcp`

Starts an MCP (Model Context Protocol) server over standard I/O for integration with AI coding assistants (Claude Desktop, Antigravity, OpenCode):

```bash
exoproc mcp
```

### `exoproc daemon`

Starts the background daemon bridge (used primarily on Linux / Wine):

```bash
exoproc daemon --port 43370
```

## Programmatic Client: `ExoprocClient`

You can also embed `exoproc` into your own Node.js or Bun applications:

```typescript
import { ExoprocClient } from 'exoproc';

const client = new ExoprocClient({
  baseUrl: 'http://127.0.0.1:43370',
});

// Attach to process
await client.attach({ pid: 12345 });

// Capture screenshot
const imageBuffer = await client.captureScreenshot();

// Execute remote script
const result = await client.runScript({
  code: 'return mc.thePlayer.getHealth();',
});
```
